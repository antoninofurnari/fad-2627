The course

The course is organised in two modules.

Module 1 — Statistical data analysis. We build the vocabulary of data (description, probability, association, distributions), then use inference and regression models to explain a phenomenon, and close with causal reasoning — why adjusting for a variable in a regression is a causal act, and when it is not enough — and with how to tell the story honestly.

Module 2 — Predictive analysis and data representation. The goal changes from explaining to predicting: empirical risk minimisation, baselines, splits and cross-validation; the same models re-read as predictors, plus a few new ones; and ways to represent data — features, clusters, densities, principal components — in the service of the analysis rather than as an end in themselves.

Each module ends with a written test. The practical work is a project on an assigned dataset, carried out in two parts and presented at the exam. The schedule says what happens when.

The official syllabus — programme, textbooks, assessment rules as filed with the university — is on the degree course pages, which are the version that counts.

Lecture notes

These notes are the written companion to the lectures. Every chapter mixes explanation, runnable Python and figures; the code you see is the code that produced the figures.

Download the whole book (PDF)

Every chapter in one file, in the order of the lectures, with a bookmark for each one. Each chapter can also be downloaded on its own from the top of its page.

How to use them

  • Read online. Each chapter has a table of contents on the right and a Code menu at the top to show or hide the source of every figure.
  • Run them. Each chapter can be opened in Google Colab from the link at the top of the page, or downloaded as a notebook and run locally.
  • Practise. Chapters end with exercises, and the self-assessment quiz draws its questions from the same material.

Before you start

The course assumes you can read and write basic Python. The first lecture assigns a self-study crash course covering the language and the data-science stack (NumPy, pandas, matplotlib) — the three notebooks under Lecture 1 in the sidebar. Work through them in the first week; they are not covered in class.

Project

The practical part of the exam is a data analysis project on an assigned dataset, carried out in two parts — one per module — and presented at the exam. The work happens in a GitHub repository forked from the course template; if you would rather not use GitHub, a zip by e-mail is accepted.

Template repository Parte 1 Parte 2

How it works

  • Groups of one to three students.
  • Register the group with the course form linked on Teams, by Sunday 11 October. The form is how the groups are formed; it is not the place where the dataset is chosen.
  • Each group is then assigned a dataset by e-mail, in the fourth week. The analysis is yours to design: the template says what a complete analysis contains, and you write the questions.
  • You fork the template and work in your fork. Three ways to hand a part in, whichever suits you:
    • fork public and send the link;
    • fork private and add antoninofurnari as a collaborator;
    • or send a zip of the repository by e-mail.
  • The presentation at the exam doubles as the oral examination: every member speaks and answers questions about the analysis.
Released Due
Part 1 — describing, inferring, explaining (Module 1) published from the start; the dataset arrives on session 7 reviewed in class at the first written test
Part 2 — predicting and representing (Module 2) published from the start; walked through in class on session 20 end of January
Presentation — early February, before the first exam session

Part 1 is looked at in class during the session of the first written test: the teacher and the tutor go round the desks and read what each group has. It does not have to be finished, and it is not marked that day — the point is to catch a wrong turn while there is still time to correct it. There is one submission, at the end of January: one notebook holding both parts, marked as it stands then.

Both briefs are published from the start, so nothing is held back. The two parts follow the two modules: Part 1 is the statistical analysis, up to the regression models that explain the phenomenon and the causal reading of their coefficients; Part 2 is the predictive half, plus the ways of representing the data. So the material for each part is taught before the session that reviews it. Part 2 is walked through in class before the winter break, and it is not tied to the second written test, which is a test only.

Ground rules

  • The notebook must run top to bottom in a clean environment. If it does not, the submission is returned before it is marked.
  • Data files are never committed. The repository explains how to obtain them.
  • Strip notebook outputs, or keep the notebook under 5 MB.
  • A contribution breakdown and a declaration of how generative AI was used are both mandatory.
  • A submission consisting only of slides is not marked.
  • A negative result, argued with evidence, is worth full marks. An analysis that honestly concludes “the data cannot answer this” is a good analysis.
